Source-first paper adjudication

Upstream method: start from the papers themselves, adjudicate what each source supports, limits, refutes, or leaves unknown, then allow claims and wiki prose to follow.

Input: many papersWork: organize support, limits, disagreement, uncertaintyOutput: wiki prose + claim/evidence/trust surfaces

Pipeline: papers → source positions → claim/status ledger → debate map → wiki prose

When to use it

Use when

When source links may be topical rather than evidential, support status is uncertain, claims have inflated scope, or the team needs a stronger evidence foundation before writing.

Do not mistake it for

Not ideal for quick display cleanup or already-safe prose polishing; it can stall if every minor label is pushed back to full source adjudication.

Method details

Inputs

  • The paper corpus, source texts, abstracts/full-text access labels, metadata, quoted spans, rhetorical zones, and target scientific questions.
  • Existing claim IDs may be comparison targets but are not authoritative.

Work

  • Read/adjudicate source positions before defending any claim.
  • Label source stance as supports, refutes, mixed, limited, no-info, or background/topical only.
  • Lift adjudicated evidence into claims and debate-map positions only after the source role is explicit.

Outputs

  • Source-position ledger with quotes, locations, stance, scope, and access level.
  • Accept/limit/reject/no-info table for candidate claims.
  • Coverage gaps, countercases, and paper-to-wiki readiness notes.

Stop gates

  • A source is used because it is merely about the topic rather than findings-level evidence.
  • An abstract-only source is treated like full support without a label.
  • Counter-evidence or uncertainty is filtered out instead of recorded.
