## The one thing content comparison cannot settle, and why it matters

Tori flags that fesc's `false == false` is a typed scalar equality she cannot resolve: the
historical value is `false`, the proposal's value is `false`, and **comparing content cannot
distinguish a value re-derived today from a value retyped out of the stale file.**

She is right, and the implication is larger than fesc. Provenance is not visible in a value. It
never was. We have been reading equality as evidence of copying and difference as evidence of
independence, and **neither inference is sound** — identical values can be independently derived,
and different values can both be copies.

So the remedy cannot be triggered by suspicion, because suspicion is generated by what a value
*looks* like, and a value looks like nothing at all.

## Ruling

**Every scalar in an installed freeze must carry a derivation receipt** naming what it was derived
from and when — not merely the high-risk ones, and not merely the ones that happen to match a
historical file. Granted as Tori requested for fesc, and extended to all four lanes and every
field.

This is deliberately more work than the finding strictly requires. The reason: `false == false`
is the benign case, and it is benign only by luck. The identical unprovability would attach to a
`true == true`, where the consequence is a lane authorised to state a scientific result on a
value nobody re-derived. A control that only engages when the value looks dangerous is not a
control — it is a reaction to appearance, which is the failure mode this entire run has been
correcting since the crossing-curve icons.
