1. Quote: "C1 — denominator. Claims enumerated, attempted, and `NOT_ATTEMPTED`, printed before any tally."
   Defect: internal contradiction. §3 abolished NOT_ATTEMPTED ("The old `NOT_ATTEMPTED` class was incoherent") and moved exclusions to a separate ledger, but C1's pass condition still demands a count of the abolished class. The control cannot be executed as written; a seat must invent a category or leave C1 unverifiable. The redesign removed the class from the outcomes but not from the control that audits them.
   Replacement: "C1 — denominator. Included claims enumerated, per-claim outcomes assigned, and exclusion-ledger entries counted, all printed before any tally; the reported denominator equals the included count and the exclusion count is printed alongside it. `C1_DENOMINATOR_PRINTED=PASS`."

2. Quote: "120-second cap on symbolic operations with `SYMBOLIC_TIMEOUT` as a reportable outcome" — against §3's five per-claim classes.
   Defect: a timed-out claim matches no §3 outcome (REPRO_FAILED requires the arithmetic to have completed and disagreed) and §4 gives no routing — it is unstated whether timed-out claims are "unresolved" under CENSUS_PARTIAL. A mandated stop lacks an outcome class, so a real result falls into none.
   Replacement: add to §3: "`REPRO_TIMEOUT` — the harness's 120-second cap fired before the arithmetic completed. Report the command and elapsed time. A claim with this outcome counts as unresolved for §4." And amend §4 class 2: "some claims unresolved after two attempts, including any `REPRO_TIMEOUT`."

3. Quote: "If the enumeration is itself contested between the two seats beyond a stated tolerance, stop and report"
   Defect: no tolerance is stated anywhere in the operative text. The only value given lives in the §10 V2 history row ("enumeration tolerance set to zero"), which is metadata, not method; CENSUS_DENOMINATOR_DISPUTED likewise says "disagree after two reconciliation attempts" with no measure. A stop condition riding on an unstated quantity is the stated-not-enforced failure this redesign exists to escape.
   Replacement: "If the two seats' included-claim sets differ at all — the tolerance is zero — and the disagreement survives two reconciliation attempts, stop and report under `CENSUS_DENOMINATOR_DISPUTED`."

4. Quotes: "`REPRO_AFTER_CHOICE` — it follows only once a quantity is chosen, fitted or imported." and C3's "`origin: DERIVED|CHOSEN|FITTED|IMPORTED|UNDECLARED`".
   Defect: the document never states the rule mapping the ledger's origin field to REPRO_EXACT versus REPRO_AFTER_CHOICE, and C3's script machine-checks values and statuses but not origin labels. A value the paper prints but does not declare (e.g. "we take α = 0.1") can be filed either way, and a seat can move an outcome by asserting DERIVED over CHOSEN with nothing mechanical to contradict it. Two classes can claim one result, and the deciding field is satisfiable by assertion.
   Replacement: append to §3: "Routing rule: the outcome is `REPRO_EXACT` iff every consumed input is `STANDARD` or has origin `DERIVED`; any consumed input with origin `CHOSEN`, `FITTED`, `IMPORTED` or `UNDECLARED` makes the outcome `REPRO_AFTER_CHOICE`, naming each such quantity." And extend C3: "each origin classification carries the source_file and source_line of the passage establishing it; the script asserts that citation is present, and the C6 audit re-derives the origin labels."

5. Quotes: "`REPRO_BLOCKED` — an input traces to a source we cannot obtain. Name it." and "`REPRO_INPUT_ABSENT` — an input the equation needs is `ABSENT` from the paper".
   Defect: an input the paper attributes to another work without printing the value is simultaneously absent from the paper and traced to a source outside the pinned set that the seat cannot obtain. Both classes claim it; no precedence rule exists. Mutual exclusivity fails.
   Replacement: "`REPRO_INPUT_ABSENT` takes precedence: any input whose value is not printed in the pinned corpus is `REPRO_INPUT_ABSENT` regardless of external obtainability. `REPRO_BLOCKED` applies only when a source inside the pinned set cannot itself be obtained; name it."

6. Quote: "`REPRO_EXACT` — the printed number follows, within its own stated precision, from printed + standard inputs only."
   Defect: when the paper states no precision, the EXACT/FAILED boundary is undefined and becomes seat judgement; one real arithmetic result can be argued into either class.
   Replacement: "`REPRO_EXACT` — the printed number follows from printed + standard inputs only, agreeing within the paper's stated precision; where no precision is stated, agreement must hold to ±half a unit of the last printed significant digit, else the outcome is `REPRO_FAILED`."
