Finding 2 — crux, provenance not transitive.
Quote: "`DERIVED` (obtained from the paper's own equations)" (§3)
Defect: A value the paper computed from a chosen input and printed with its own numeral is "obtained from the paper's own equations", so its record reads origin=DERIVED and it is admissible — the chosen ancestor is laundered one derivation step down, and downstream claims file REPRO_EXACT. Finding 3 — schema cannot express STANDARD origin.
Quote: "origin: DERIVED|CHOSEN|FITTED|IMPORTED|UNDECLARED" (C3)

Finding 4 — per-claim classes not exhaustive.
Quote: "`REPRO_FAILED` — admissible inputs are sufficient but the arithmetic does not give the paper's number." (§3)
Defect: If an inadmissible input is required and the number still does not follow even after using it, no class applies: not REPRO_AFTER_CHOICE (defined by "it follows"), not REPRO_FAILED (its precondition fails), not REPRO_INPUT_ABSENT ("a value was supplied"). A number propped up by a chosen value that still fails to reproduce is a mundane referee result and must land somewhere. Relatedly, when one input is ABSENT and another traces to an unobtainable source, precedence between REPRO_INPUT_ABSENT and REPRO_BLOCKED is unstated.
Replacement: "`REPRO_FAILED` — the arithmetic does not give the paper's number, whether or not admissible inputs alone were sufficient. Report both numbers; if an inadmissible input was used, name it and its origin. Wording: 'unreproduced from the stated inputs,' not 'error.' Where more than one terminal condition holds, file the first in this order: REPRO_INPUT_ABSENT, REPRO_BLOCKED, REPRO_NOT_EVALUABLE, then the arithmetic outcomes." (Mutual exclusivity is preserved: EXACT = follows on admissible inputs only; AFTER_CHOICE = follows only with an inadmissible input; FAILED = does not follow.)
