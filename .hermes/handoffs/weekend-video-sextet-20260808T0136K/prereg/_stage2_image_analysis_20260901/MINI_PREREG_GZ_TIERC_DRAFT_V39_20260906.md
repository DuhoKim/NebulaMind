## 3. Coordinate parsing and angular match

3.1 GZ1 sexagesimal RA is parsed as `15 * (hours + minutes/60 + seconds/3600)` degrees.

3.2 GZ1 sexagesimal declination is parsed with the printed leading sign applied to the whole absolute quantity `degrees + arcminutes/60 + arcseconds/3600`.

3.3 DESI RA and declination are parsed as IEEE-754 binary64 degrees in ICRS.

3.4 Every coordinate and probability must exist, parse uniquely, and be finite. RA must satisfy `0 <= RA < 360`; declination must satisfy `-90 <= Dec <= 90`; each probability must satisfy `0 <= P <= 1`.

3.5 Angular separation is the great-circle separation on the unit sphere, computed in binary64 from ICRS coordinates.

3.6 The inclusive match radius is exactly 1.0 arcsecond. Equality at 1.0 arcsecond is accepted.

3.7 All candidate DESI objects at separation `<= 1.0 arcsecond` are enumerated. A nearest-neighbour query that returns only one candidate is not sufficient to prove uniqueness.

3.8 Duplicate `OBJID` rows within or across GZ1 Tables 2 and 3 are a catalogue integrity failure; none is resolved by table priority.

3.9 A GZ1 object with zero DR10-south candidates is unmatched and not eligible.

3.10 A GZ1 object with two or more DR10-south candidates inside 1.0 arcsecond is ambiguous and not eligible, even if one candidate is strictly nearer.

3.11 After rule 3.10, if two or more GZ1 objects point to the same DR10 object, all GZ1 objects in that collision component are ambiguous and not eligible. No closest, highest-vote, or table-priority winner is chosen.

3.12 The ambiguity exclusions are computed from coordinates and identifiers before `P_CW`, `P_ACW`, image pixels, or instrument outputs are consulted.

## 4. Exact disjoint Tier-C definition

4.1 Tier assignment priority is A, then B, then C, at the GZ1-object level.

4.2 For each GZ1 object, first enumerate all Tier-A candidates within 1.0 arcsecond. If at least one exists, assign that GZ1 object to A and stop.

4.3 Otherwise enumerate all Tier-B candidates within 1.0 arcsecond. If at least one exists, assign that GZ1 object to B and stop.

4.4 Otherwise apply the complete DR10-south matching and ambiguity rules in §3. A GZ1 object is Tier C only if it has exactly one DR10-south candidate and that DESI object survives the one-to-one collision rule.

4.5 Thus Tier C is disjoint both from the 49,211-object Tier-A mask and from every member of the 65,060-object protected parent at the inclusive 1.0-arcsec radius. A parent match excludes the GZ1 object even if another non-parent DESI candidate exists.

4.6 The protected-parent filter is applied before any image-path resolution, file opening, pixel access, rendering, instrument call, or label comparison.

4.7 The eligible GZ1 label is clockwise iff `P_CW >= 0.8` and `P_ACW < 0.8`.

4.8 The eligible GZ1 label is anticlockwise iff `P_ACW >= 0.8` and `P_CW < 0.8`.

4.9 The threshold is inclusive: equality at 0.8 qualifies.

4.10 If neither probability reaches 0.8, the object is below threshold and is not in the frozen analysis sample.

4.11 If both probabilities reach 0.8, the label is contradictory and the study refuses with `DATA-INTEGRITY-FAIL`; it is not broken by a larger probability.

4.12 No `P_CW + P_ACW` threshold, vote-count threshold, magnitude cut, or later visual-quality cut applies.

4.13 The final eligible unit is one unique pair `(GZ1_OBJID, DR10_RELEASE, DR10_BRICKID, DR10_OBJID)` satisfying every rule above.

4.14 Pair rows are canonically sorted by the integer value of `GZ1_OBJID`, then integer `DR10_BRICKID`, then integer `DR10_OBJID`.

## 8. Frozen geometry and rendering

8.1 Each scientific raster is exactly 128 by 128 pixels and subtends exactly
33.536 by 33.536 arcseconds at 0.262 arcsecond per pixel.

8.2 The output is a TAN WCS centered on the exact catalogue `(RA, Dec)` parsed as binary64; coordinate rounding to a source pixel is prohibited.

8.3 In FITS one-based pixel-center convention, `NAXIS1=NAXIS2=128`, `CRPIX1=CRPIX2=64.5`, `CRVAL1=RA`, and `CRVAL2=Dec`.

8.4 The output CD matrix in degrees per pixel is exactly `CD1_1=-0.262/3600`, `CD1_2=0`, `CD2_1=0`, `CD2_2=+0.262/3600`.

8.5 There is no object-dependent rotation. The display and instrument raster are north-up and east-left.

8.6 Parity is strictly preserved through WCS transforms, array-axis conversion, storage, display, and model input. The instrument's explicit mirror is the sole chirality-changing transform.

8.7 An effective source-to-output Jacobian with the wrong parity refuses the cutout and yields `WRONG-PARITY-REFUSAL`; it is never corrected by a flip.

8.8 The Tier-C brick manifest carries every primary and neighbour brick the frozen closure identifies, and all of them are acquired and sealed. **Stitching across bricks is NOT exercised by this study, and a raster is never composed from more than one brick.** Every object is rendered from its single catalogue primary brick under §8.8a. A home-brick seam is not an exclusion reason because no object has one: measured over all 12,217 frozen objects, the primary brick contains the whole 128-by-128 raster and its bilinear stencil in every case, with a worst-case margin of `17.6` pixels and a first-percentile margin of `27.8` pixels. The reason is geometric: a DR10 brick array spans `0.2620` degrees while brick centres are spaced `0.2500` degrees, so adjacent bricks overlap by `164.9` pixels, far exceeding the `65` pixels of half-width the raster and its stencil require.

8.8a **Single-brick rendering, and why the previous promise could not be kept.** V1 through V13 stated that neighbouring bricks are stitched before reprojection. The pinned renderer could not do that on real data: it accepted a cross-brick pixel only where the neighbour's grid aligned to `1e-6` pixels, and adjacent Legacy Surveys bricks are separate TAN projections about different tangent points whose lattices differ by of order `1e-1` pixels. That path could therefore never succeed, and it had never been executed — the renderer's own fixture used synthetic tiles that share a lattice, and the study had never reached rendering. Rather than leave a signed sentence the code cannot honour, the promise is corrected to what is both true and sufficient: single-brick containment, enforced by §8.8b, with no stitching at all.

8.8b **Containment is a precondition, checked before sampling.** The source used for an object is the brick named `PRIMARY_BRICK` for that object in the frozen sample manifest of §6.1. Before any sample is taken, that source must contain every one of the 16,384 output positions AND the 2-by-2 bilinear stencil of each. If it does not, the object yields `SINGLE-BRICK-CONTAINMENT-FAIL`, which is a `DATA-INTEGRITY-FAIL` under §13.4; there is no fallback to another brick, no partial render, and no object-level deletion. If more than one source is supplied and no primary is named, the render refuses with `AMBIGUOUS-SOURCE-SELECTION`. Selection is therefore never a function of the order in which sources are passed.

8.9 Exactly one deterministic bilinear reprojection maps the SINGLE SELECTED SOURCE BRICK of §8.8b to the output WCS. There are no stitched inputs: exactly one brick contributes to a raster. Reprojection returns binary64; normalisation is binary64; only the normalised tensor is materialised, once, as little-endian float32 (§8.9d, §8.15b).

8.9a **Contamination is identified on the SOURCE grid, by exact bitwise test, and maskbits are never interpolated.** For the single selected source brick of §8.8b, a boolean rejection mask is computed from that brick's INTEGER `maskbits` plane by `(maskbits & REJECT_MASK) != 0`, where the rejecting bits are exactly `1 BRIGHT`, `3 SATUR_R`, `6 ALLMASK_R`, `10 BAILOUT`, `13 CLUSTER` (V36: `11 MEDIUM` is NO LONGER rejecting — §8.9b) per `https://www.legacysurvey.org/dr10/bitmasks/`. The pinned implementation is `study_renderer/pixel_rejection_v2.py`, SHA-256 `075d73460645ab4c8353a468c8f3a7eabed8e9339198ea26f0dd51a35db02e54`, fixture `study_renderer/test_pixel_rejection_v2.py`, SHA-256 `9468c0122181dcc2119b60c168fbdecbba87daf60dfc696a745ed0a86ef4020c`, real run 6/6 (the fixture also runs the V35 module `study_renderer/pixel_rejection.py`, SHA-256 `8f66bc1c61173648f11386eb17f2d5afd3c3f1a338aee5bf3e11fe9aad950818`, on the same inputs and asserts that it replaces a MEDIUM pixel and ignores a zero-exposure pixel — so the fixture FAILS on the V35 behaviour). V36: the rejection mask is `bit_rejection_mask(maskbits) | zero_exposure_mask(nexp)` — every source pixel whose INTEGER `nexp-r` count is `0` is rejected exactly like a masked pixel (§8.12); the module's `validate_planes` REFUSES a non-integer maskbits or nexp plane, a NEGATIVE value in either (a bit field or a count cannot be negative), planes of differing shape, and a non-finite image value (fixture-asserted, each), so a resampled or corrupt plane cannot be tested by mistake.

8.9b Bits `0` (`NPRIMARY`), `12` (`GALAXY`) and, from V36, `11` (`MEDIUM`) are deliberately NOT rejection bits: `NPRIMARY` marks pixels in the overlap band adjacent bricks share, which carry valid flux and are exactly the pixels a near-edge raster relies on under single-brick containment; `GALAXY` marks SGA large-galaxy pixels, which are frequently the TARGET. Bits `2` and `4` are other-band. `MEDIUM` (V36, per the signed option A rule V15 §6): it is CARRIED through §8.9d and the number of output pixels carrying it is reported per raster as a covariate (`pixel_rejection_v2.medium_count`); V15 §6 records seat B's position that the MEDIUM reading is an empirical claim, not a definitional one, and specifies a label-blind perturbation study on the development TUNING set (chi with MEDIUM pixels kept versus replaced by the lower median; sign-flip rate reported) as the filed disclosure of what the relaxation costs — the rule does not depend on its outcome. These exclusions are recorded so the choice is visible rather than accidental, and the fixture asserts each of the five rejects and each of the five does not.

8.9c **Rejected source pixels are replaced before reprojection**, so no contaminated value enters the bilinear operator. The replacement is the LOWER median of the accepted source pixels — for an even count the lower middle value, so the result is always an observed pixel value and never an average of two. A source with fewer than `16` accepted pixels yields `NO-ACCEPTED-PIXELS`, a `DATA-INTEGRITY-FAIL` under §13.4, because a median over a handful of survivors is not a background estimate. No interpolation, smoothing, inpainting or randomness is used.

8.9c-i **The estimator was measured, not assumed.** Replacing with a global sky median imports the brick's overall background into a galaxy's neighbourhood. Measured on synthetic spirals at the Tier-C median amplitude with the contaminant outside `T`, n=120 each: a global-brick median and a local-annulus median both give sign accuracy `1.000` against ground truth and `1.000` against the uncontaminated image. The estimator choice does not move the sign at this contamination level; the global median is used, and the alternative is recorded as measured-equivalent rather than dismissed.

8.9d **Which OUTPUT pixels the contamination touched is read exactly, not propagated as a weight.** The renderer samples the integer planes — `maskbits` and `nexp` — by NEAREST NEIGHBOUR, which is an index selection rather than a resampling, and returns them as integers. The rendered `maskbits` plane therefore still carries true bit semantics, and an output pixel is FLAGGED if and only if its own rendered maskbits value has a rejecting bit set OR (V36) its own rendered `nexp` value is `0` (`pixel_rejection_v2.flagged_output(maskbits, nexp)`); `MEDIUM` never flags. No fractional contamination weight exists and none is needed. PRECISION BOUNDARY (V38): the renderer returns and digests the reprojected image in BINARY64; the consumer computes the §8.15 normalisation in binary64 and materialises the normalised tensor ONCE as little-endian float32 (65,536 bytes); no earlier float32 materialisation exists.


8.9e The ordering of §8.9a through §8.9d is binding and corrects two defects, both introduced by earlier drafts of this document. In one, rejection ran AFTER reprojection, so a contaminant was smeared into its neighbours before anything rejected it. In the next, the prose forbade interpolating `maskbits` while the pinned renderer bilinearly interpolated it anyway, returning a float plane containing values such as `2.2e-10` where the input held only `0` and `8`; the clause and the code were written in the same session and contradicted each other, and the contradiction was found by a referee that executed the renderer rather than reading it. Both are removed by identifying and replacing on the source grid and by sampling every integer plane with nearest neighbour.


8.10 Resizing, further interpolation, rotation, transpose, PSF homogenization, padding, wrapping, reflection, intensity-conditioned source choice, and chirality-conditioned processing are prohibited. The source-grid rejection and replacement of §8.9a-§8.9c, the mask carriage of §8.9d, and the single amplitude normalisation of §8.15 are the only exceptions, admitted here explicitly rather than by silence. None moves a pixel, none adds an interpolation beyond §8.9's single one, and all are chirality-blind: the rejection is keyed only to the published integer maskbits and integer exposure-count planes under §8.9a (V37), the replacement is a scalar median, and the normalisation is a scalar division.

8.11 The identical reprojected raster is supplied to the unmirrored branch and to the instrument's exact mirror operation; the mirrored branch is not separately reprojected.

8.12 **Coverage (V36).** Every output pixel requires a valid image value and integer `maskbits` and `nexp-r` values from the verified single selected source brick of §8.8b; any MISSING or NON-FINITE required value still yields `DATA-INTEGRITY-FAIL` for the study, not an object-level deletion. A source pixel whose `nexp-r` count is `0` is no longer a whole-raster refusal: it is REJECTING under §8.9a — replaced by the §8.9c lower median of the ACCEPTED source pixels (the unexposed pixel never enters that median) and FLAGGED under §8.9d — in place of V35's all-or-nothing rule. 8.14 **Refusal on excessive or central contamination.** Let `F` be the count of output pixels FLAGGED under §8.9d, out of the 16,384 pixels of the raster. 8.14a The object is REFUSED, and is not measured, if either (i) `F > 819`, that is more than 5% of the raster is flagged, or (ii) any flagged pixel lies inside `T`. 8.15 **Amplitude normalisation.** Let `C` be the raster after §8.9c replacement and §8.9 reprojection. Define `peak = max(C[48:80, 48:80])`, the maximum over the central 32-by-32 aperture, evaluated in binary64. The normalised raster is

materialised as little-endian float32, C-order, shape `(1, 128, 128)`. `peak` is journalled per object. This is the only intensity scaling permitted anywhere in the pipeline.

8.15a **Objects larger than the aperture.** An object whose light extends beyond the central 32-by-32 aperture is normal and is not refused on that ground: the aperture is a scale estimator, not a containment requirement, and `T` in §8.14 — not the aperture — is what protects a large object from contamination. 10.7 Define mapping strength `d_map = abs(2*p_map - 1)`.

10.8 The fixed mapping margin is 0.10.

10.9 A relative mapping is chosen iff `d_map >= 0.10`. Equality at 0.10 chooses a mapping.

10.10 If `p_map > 0.5`, signed GZ label is `s=g`. If `p_map < 0.5`, signed GZ label is `s=-g`.

10.11 If `p_map = 0.5`, then `d_map=0`, so the rule necessarily reports `UNDETERMINED-SIGN`.

10.12 If `d_map < 0.10`, report `UNDETERMINED-SIGN` and stop before opening or measuring any estimation-split image.

10.13 Mapping-split agreement is used only to choose or refuse the relative mapping. It is not pooled into the reported concordance estimand.

## 11. Sample adequacy

11.1 The mapping split requires at least `n_map = 100` successfully prescribed objects and the estimation split requires at least `n_est = 400`.

11.2 These floors are fixed from the two-sided 95% Wilson interval at worst-case `p=0.5`: its approximate half-width is at most 0.098 for n=100 and at most
0.049 for n=400, using `z=1.959963984540054`.

11.3 Adequacy is evaluated on the frozen eligible split before measurement. Because no post-measurement deletion is permitted, any later missing result is a failure verdict, not a reduced denominator.

11.4 If either frozen split misses its floor, report `INSUFFICIENT-SAMPLE` and open no real image.

## 12. Estimands and uncertainty

12.1 The primary estimand is the signed inter-method agreement rate on the estimation split: `p_hat = count(machine_sign = signed_GZ_label) / n_est`.

12.2 The numerator and denominator include every frozen estimation-split object except the two ESTIMATION-SPLIT objects excluded pre-pixel by §7.8e, which excludes three objects in total across both splits.

12.2a **The denominators are fixed here as exact integers, before any pixel.** The frozen manifest — `TIER_C_SAMPLE_MANIFEST_V13_20260904.csv`, pinned in §6.6 — holds 12,217 objects, 2,469 mapping and 9,748 estimation. §7.8e excludes three: one mapping object (`GZ1_OBJID=587731514233454814`, brick `0576p012`) and two estimation objects (`GZ1_OBJID=587731511549624713`, brick `0591m010`; `GZ1_OBJID=587742633352495747`, brick `2640p332`). Therefore **`n_map = 2,468` and `n_est = 9,746`**, totalling 12,214. Both remain far above the §11.1 floors of 100 and 400, so the exclusion does not create or relieve an adequacy problem. A run computing any other denominator is `DATA-INTEGRITY-FAIL`.

12.3 The complementary rate is `q_hat = 1 - p_hat` and means signed inter-method disagreement, not an error rate against truth.

12.4 The sign-invariant robustness statistic is `R = abs(2*p_hat - 1)`.

12.5 Report the two-sided 95% Wilson score interval for `p_hat` with `z=1.959963984540054`:

`center = (p_hat + z^2/(2*n_est)) / (1 + z^2/n_est)`;

`half = z/(1 + z^2/n_est) * sqrt(p_hat*(1-p_hat)/n_est + z^2/(4*n_est^2))`;

`CI95 = [center-half, center+half]`.

12.6 Report the complementary interval as `[1-CI95_upper, 1-CI95_lower]`.

12.7 No bootstrap, continuity correction, multiplicity adjustment, weighting, covariate adjustment, subgroup selection, or alternative interval is primary.

12.8 Counts by GZ1 class and split may be reported descriptively if fixed in the completion schema; no subgroup concordance claim is authorized.
