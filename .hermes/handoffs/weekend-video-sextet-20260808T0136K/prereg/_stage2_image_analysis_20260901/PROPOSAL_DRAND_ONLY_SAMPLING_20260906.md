## In one paragraph
Use ONE public randomness source — the drand mainnet default chain — and drop NIST. Commit at approval time to a future drand round fixed by the pinned formula; that round's value is a threshold BLS signature by the League of Entropy over a fixed message, so it is unique, unpredictable before its scheduled time, and verifiable by anyone against the chain's public key — including by us, with actual cryptographic verification, as exhibited below. Because the seed is then a pure function of (round number, chain public key), no relay, no operator and no collection time can change it; the first-collection lever that sank V16–V19 and that the signed V15 also carries does not exist in this design.

## 4. Residual trust, stated plainly
- **The League of Entropy's threshold key.** The seed is unpredictable and unbiasable only if fewer than the threshold of drand nodes collude; if they collude, they can bias a future round. We cannot check that; nobody outside the network can.
- **The pinned public key's authenticity.** We pin the key served by the network's own info endpoint and cross-checked against public documentation; if the pin itself were wrong, every verification would be against the wrong chain. Mitigation: the pin is in the signed text and anyone can compare it to the network's published key.
- **Relay availability.** If fewer than two pinned relays serve the round, the verdict is RETRY — a delay, never a different value (the round's value is fixed forever once produced; any relay serving it later gives the same bytes or fails verification).
- **The verifier implementation.** py_ecc is a pure-Python BLS implementation pinned by version; a bug there could accept an invalid signature. Mitigation: the exhibit's negative controls (tamper, wrong key) and, if Duho wants, a second independent verifier (e.g. drand's own CLI) at collection.
- **What is no longer trusted:** NIST's certificate, its AIA chain, its next-pulse link, and any relay's honesty (a dishonest relay cannot forge a BLS signature).
