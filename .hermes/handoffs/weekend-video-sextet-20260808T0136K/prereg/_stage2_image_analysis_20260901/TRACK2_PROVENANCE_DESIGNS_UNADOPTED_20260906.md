## (a) Authentic GitHub event validation — `authenticate_event`
| | |
|---|---|
| **What it checks** | The retained PushEvent (the identity's witness) must appear VERBATIM — canonical SHA-256 equal — in a LIVE retrieval of the pinned repository's events (`gh api repos/DuhoKim/NebulaMind/events`, the same call the builder makes), must name the pinned repository, the protected ref and the approval commit, and must be the EARLIEST qualifying event in that retrieval. |
| **Outcomes** | AUTHENTIC; FORGED (absent from the live feed, or not the earliest, or wrong repository); UNAVAILABLE (API error → retry, nothing else changes); EXPIRED (the feed no longer reaches the event's time). |
| **When it runs** | In the driver at `load_identity`, i.e. at `tune` and at `holdout` — both happen within days of the approval, well inside GitHub's feed window (about 90 days / 300 events per repository). |
| **What it costs** | Network at driver time (read-only, the authenticated `gh` CLI, BUILT: `retrieve_events` with pagination and named failure kinds); a retry path when GitHub is down (UNAVAILABLE → RETRY); and, for a driver run after the window, a SECOND retrieval receipt taken independently inside the window (BUILT: `write_events_receipt` by Blanc from the OPS session — origin `{actor: blanc-ops, session: OPS}` named by Duho — committed and pushed once; `verify_events_receipt` accepts EXPIRED only when the retained event is verbatim in that receipt, the receipt was added once and never touched, and its commit is an ancestor of the LIVE remote head). |
| **Trusted afterwards** | GitHub's server clock and the integrity of its events feed; the `gh` session's authenticity; for the EXPIRED path, Blanc's independence from the lane. |
| **No longer trusted** | The identity's own retained event bytes, their digest, and the provenance block — attack 1 becomes FORGED (row 9b). |
| **Unavailable / inconsistent** | UNAVAILABLE = RETRY (no seed, no verdict); FORGED = DATA-INTEGRITY-FAIL, the identity is dead; EXPIRED without a receipt = refused; the rule text would say all three. |
| **Recommendation** | ADOPT (a) with the live re-query mandatory and the second receipt mandatory at freeze time (taken by Blanc within the window, so the EXPIRED path is always covered). Cost is one network read per driver run and one OPS receipt per approval. |

## (b) Externally witnessed history continuation — `validate_continuation`
| | |
|---|---|
| **What it checks** | The collection history's FIRST commit must be the witnessed HISTORY-OPEN commit (the collector's genesis, committed and pushed to the protected branch immediately, and witnessed by its own server-side PushEvent exactly like the approval record — that PushEvent is the external anchor); every later commit touching the file must carry a blob that is a strict byte-prefix EXTENSION of the previous one (append-only, verified through git objects, not through the file's own hashes); the working-tree bytes must extend the last committed blob. |
| **Why it closes C3** | A rebuilt history (fresh genesis) is not an extension of the committed one; a deleted suffix is shorter than the last committed blob; a reset before the first freeze is visible because the earlier commits cannot be removed from a branch protected against force pushes and deletion. Rows 9c/9d, and `test_b_history_continuation_through_git` (rebuilt, truncated, restored-after-rebuild, wrong open commit: all refused). |
| **What it costs** | ONE PUSH PER COLLECTOR/BUILDER ATTEMPT — every history entry is committed and pushed AS IT HAPPENS (the collector and builder CLIs would do it themselves), NOT one push per freeze (Blanc's condensation to Duho was wrong; corrected here); the history-open commit needs its PushEvent retained like the approval record's (W3 machinery reused); the validator ASKS THE REMOTE (`ls-remote`) at every load — network at driver time; a history that was never pushed cannot be used; a failed push = PENDING-PUSH until acknowledged; a rejected push = DIVERGED, dead. |
| **Trusted afterwards** | The remote's answer to `ls-remote` over TLS to github.com for the pinned URL; server-side branch protection on `feat/paper-workflow-v2` (Duho's GitHub setting, already required by §7); GitHub's PushEvent for the open commit. In the tests the remote is a LOCAL BARE repository with non-fast-forward receives denied — labelled; it is the same git command minus TLS. |
| **No longer trusted** | The file's own hash chain as evidence of custody (it stays as tamper-evidence within a blob); the operator's clock. |
| **Unavailable / inconsistent** | Remote unreachable = RETRY-REMOTE-UNAVAILABLE (nothing governs); uncommitted or unacknowledged local bytes = PENDING-PUSH (retry the push, never rebuild); a stale supplied head = STALE-EXPECTED-HEAD; a local rewrite = HISTORY-DIVERGED, and any non-extension commit on the remote ref = HISTORY-NOT-AN-EXTENSION — the history is dead and so is every identity built on it. |
| **Recommendation** | ADOPT (b). It reuses the witness already required for the approval record and the branch protection already required by §7; the only new cost is one push per attempt. |
