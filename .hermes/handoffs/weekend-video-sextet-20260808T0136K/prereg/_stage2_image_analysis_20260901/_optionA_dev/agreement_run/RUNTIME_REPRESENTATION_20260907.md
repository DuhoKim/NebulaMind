# V49 runtime representation mechanism

The runtime register retains `A1-RUNTIME-PINS-CORE-1` and its original invocation, three compact artifact pins, versions and scientific-lock checks. Its mandatory `representation` member has schema `A1-RUNTIME-REPRESENTATION-1`. The earlier exhaustive inventories are historical evidence, not an authority or a substitute for this measured register.

`runtime_probe.py` imports every declared `run_path.CODE` module, Astropy FITS/WCS and the actual py_ecc BLS implementation. It exercises generated RICE_1 FITS encode/decode, a generated TAN transformation, a NumPy FFT, a synthetic-key BLS verification and local default TLS context/opener creation. It makes no network request and invokes no RunPath stage. It then enumerates the process's module files/cache candidates and dyld images; it does not walk an installed-library tree. The new plistlib/pyexpat dependency, triggered by the required platform lock measurement, explains 423 images versus the earlier probe's 422.

The measured register contains 1,480 distinct readable files: 704 Python sources, 697 existing cache candidates, 68 extension files and 11 other native artifacts (including seven `.dylib` files). The 21 observed py_ecc module names have 42 source/cache files. There are 819 recorded module names, including the probe; a consumer that does not import the probe can have fewer. There are 423 loaded dyld images: 77 with standalone files and 346 supplied only by the active shared cache. `/usr/lib/dyld` is pinned separately because the loader is not in its own client-image enumeration. Aliases share file pins.

Every recorded real file has its individual SHA-256, resolved path and byte count. At runtime the consumer rehashes recorded artifacts before dependency preload and verifies the measured origins, newly present cache candidates, file pins and native identities after preload. Every stage entry and pre-record boundary uses this enforcement. A changed file refuses with `DIGEST-MISMATCH: <path>`; an unregistered module, cache candidate or native image also refuses by name. The two immediate pre-NumPy-import checks and the original CORE cache/source-code equality checks remain intact.

For a source-backed Python import both the source and every existing standard cache candidate are pinned conservatively. Python does not retrospectively expose whether it read that cache; disabled bytecode writing does not prevent reading one. Built-in and frozen module names are recorded with the hashed interpreter/Python framework. Namespace packages have no code artifact. Generated fileless helper modules (Cython runtime helpers, pyexpat aliases and typing helpers) have recorded identities and their producing Python/native files are in the register; no per-helper byte hash or in-memory identity is claimed. The embedding `__main__`/`__mp_main__` caller is outside this Python API's import inventory; the declared adapter and verifier are pinned.

For every missing-file image, `runtime_binding.dyld_snapshot` requires both a header address inside the active cache range and `_dyld_shared_cache_contains_path(path)`. It records the loaded name, Mach-O `LC_UUID` returned by `_dyld_get_image_uuid`, CPU type/subtype, and confirmed cache residency. The common identity is `_dyld_get_shared_cache_uuid` = `f2e86c536052388bba715a0c9b569413`, `sysctlbyname("kern.osversion")` = `25G83`, process machine `arm64`, and active cache-header architecture `arm64e`. Addresses are used only to establish residency; ASLR addresses or memory digests are not persisted. A changed common identity refuses `SHARED-CACHE-IDENTITY-MISMATCH`; changed individual image identity names the image. Missing APIs, missing UUIDs, unsupported Mach-O headers, an unstable enumeration, or an image with neither a readable file nor confirmed cache residency refuses. No nonexistent file receives a SHA-256.

Apple describes these active-cache, range and per-image UUID APIs in its [dyld SPI header](https://github.com/apple-oss-distributions/dyld/blob/main/include/mach-o/dyld_priv.h) and supplies their [implementation](https://github.com/apple-oss-distributions/dyld/blob/main/dyld/DyldAPIs.cpp). This is platform-reported cache/image identity, not a content digest, standalone image byte binding, independent signature verification or protection against a compromised OS.

**TOCTOU remains:** hashing and importing are not one locked operation. These are check-time disk pins; they do not establish the bytes the loader used, the content of an already loaded extension, relocated process pages or later memory mutations. Rechecking narrows the interval without eliminating it. Custom loaders, an untrusted embedding caller, arbitrary in-memory mutation and unobserved native resource reads remain outside the guarantee. The observed dependency set is not a proof of all possible FITS formats/network error paths: additional observed imports/images must match registered evidence or refuse at a check boundary. This is not a native loader sandbox or cross-process bit-exactness claim.

`input_readiness` now additionally requires the runtime obligation's `evidence_pin` to match the registered runtime input, then calls the actual environment verifier. Resolved prose, a boolean and a recorded TRUE cannot supply that evidence. `runtime_authoring refresh` preserves the obligation state and records only the predicate result; `resolve` first verifies the resolved A1 mapping and measured evidence, then records the evidence-backed obligation state and recomputes readiness. Neither command performs adoption, anchoring or execution.

Reproduction, from the lane root under the prescribed interpreter, PYTHONPATH and `PYTHONDONTWRITEBYTECODE=1`: `python3 -m _optionA_dev.agreement_run.runtime_probe` writes the measured JSON to stdout. `python3 -m _optionA_dev.agreement_run.runtime_authoring refresh` refreshes only authoring runtime/code/A1 pins and the computed readiness. These are authoring commands, never an automatic replacement of externally anchored expected digests.
