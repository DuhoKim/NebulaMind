# V50 runtime evidence gate

The unchanged obligation requires selected-import and OS cache-image byte binding. `A1-RUNTIME-REPRESENTATION-2` retains the compact runtime schema, invocation, versions, env_lock, per-artifact SHA-256, loaded paths, cache candidates, image identities and all existing refusals. It adds `A1-DYLD-CACHE-FILES-SHA256-1`: full-file SHA-256 for the active main cache and every subcache declared by its table. The main UUID is checked against the active process; each subcache UUID is checked against the main table. No UUID or stat value substitutes for hashing bytes. Every verification streams all files again. Unknown table formats, absent files, duplicates, omitted entries and mismatches refuse.

The empirical capture in `_tmp_v50_kit.txt` records successful complete-file hashing and readable loaded Mach-O headers/segment ranges. This implementation uses on-disk full-cache byte binding, with the image path/LC_UUID/architecture and active range/residency checks retained. The file layout is described by Apple's [dyld_cache_header and dyld_subcache_entry](https://github.com/apple-oss-distributions/dyld/blob/main/include/mach-o/dyld_cache_format.h). A test changes an actual CoreFoundation __TEXT byte in a full cache-file copy, outside its Mach-O load commands, while keeping UUIDs and OS build fixed; verification must refuse by cache-file path. Small cache-file fixtures are used for other synthetic unit tests; final live-machine verification hashes the complete real cache family.

`run_path.EVIDENCE_PREDICATES` contains one function per declared obligation. CORE checks its registered files/aliases/caches and executing consumer code. MEDIUM binds the unchanged, independently cleared producer source digest and executing producer/consumer integration. Runtime checks the evidence pin and environment, measured imports/native files and full cache-file bytes. Evidence readiness also requires complete obligation membership and no INPUT-due placeholders. Recorded statuses, explanatory text, counts, readiness flags and A1 are not resolution operands.

`_core` enforces evidence readiness and separately calls `_a1_consistency`, which rehashes all CORE rows including A1 and refuses unfamiliar or contradictory prose and recorded status claims. This check has no readiness return value. `runtime_authoring refresh` measures evidence, refreshes only allowed authoring pins, computes every status/readiness value from the predicates, then checks prose consistency. `resolve` recomputes the same evidence checks; it does not resolve by text. Neither command executes a study stage.

TOCTOU: extension modules are hashed and later imported with no lock between.
Even the immediate pre-import recheck evidences disk bytes at check time, not
the bytes the loader used (or an extension already loaded in this process).
