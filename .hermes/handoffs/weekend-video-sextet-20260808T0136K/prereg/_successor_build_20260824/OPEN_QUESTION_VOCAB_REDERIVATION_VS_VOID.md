## The collision, exactly

**Ruling 1 (22:18, the catch-all guard):** a recurring `REFUSED-UNCLASSIFIED` class cannot be
explained twice — it must be **NAMED**, which means **re-deriving the vocabulary** to carry a code

**Ruling 2 (§6.3, the void rule, standing conduct law):** *"Any post-first-real-χ change to ANY
binding rule … voids the run; only the mechanical filling of predeclared class-E values by their
frozen producers is exempt. Post-read amendments cannot cure a void."*

**The refusal vocabulary is a binding rule. Catch-all emissions happen at P1 or later — after real χ
exists. So the naming that ruling 1 requires is exactly the amendment that ruling 2 voids.** A
vocabulary re-derivation mid-run is not the mechanical filling of a predeclared class-E value; it is
a discretionary change to normative text, which is the thing the void rule exists to catch.

## What this means operationally

If a catch-all class recurs after the first real χ, the run has **no lawful continuation**: it cannot
proceed (the gate is shut until naming), and it cannot be repaired (naming voids). **The only exit is
that the run ENDS.**
